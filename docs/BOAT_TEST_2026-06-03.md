## Rotorsak (firmware)

### Signal K-svar på `PUT …/steering/autopilot/state`

```json
HTTP 202
{"state":"PENDING","requestId":"…","statusCode":202,"href":"/signalk/v1/requests/…"}
```

~1 s senare (Pi `journalctl`):

```
@signalk/signalk-autopilot SUCCESS
```

N2K exempel:

```
"Auto, compass commanded" / "Standby" / "Vane, Wind Mode" → dst 204
```

### Vad Watchy-firmware gör (bekräftat i serial)

```
[AP] HTTP PUT -> 202
[AP] command failed — no vibration
```

Firmware (`signalk_client.cpp` → `parseHttpPutResponse`) kräver på **första** svar: **HTTP 200** + `"state":"COMPLETED"`. Det matchar **inte** Raymarine/Signal K-v2-flödet.

### Konsekvenser

1. **Ingen vibration** trots lyckad styrning på P70  
2. Användaren trycker **samma kommando igen** → känns som “först funkar det inte, andra gången ja”  
3. `after state=…` direkt efter PUT visar **gammalt** läge (läser SK före N2K hunnit uppdatera)  
4. Rätt läge på klockskärm ofta först vid **session end** (~20 s) eller andra trycket  
5. `SK_PUT_SESSION_TIMEOUT_MS` = **3 s** — för kort för poll + N2K *(på flashad binär under test; repo har 12 s / 15 s poll)*

Hemma utan YDWG: samma **202/PENDING** på curl (`~/watchy-pi-curl-auto.log`).

## Vad som fungerar (P70 = sanning)

Användaren verifierade endast **P70-display** (inte loggar).

| Kommando | Pi → N2K | P70 (användaren) |
|----------|----------|------------------|
| **AUTO** | SUCCESS i logg | **Ja** (upprepade tester, t.ex. 16:10, 16:11) |
| **STANDBY** | SUCCESS i logg | **Ja** (t.ex. 16:11; ibland krävde flera försök upplevt) |
| **WIND** | SUCCESS när `command WIND` skickades (16:03:06) | Ej konsekvent verifierat av användaren; sista pass skickade **ingen** WIND |

**Pi-curl utan klocka (2026-06-03 ~16:20):** `PUT auto` → 202 → SUCCESS → användaren bekräftade **P70 i AUTO**. Bevis att kedjan inte är trasig när Watchy strular.

## Vad som inte fungerar / är svårt

### 1. Vibration och “success”-feedback

Alltid `command failed — no vibration` vid 202, även när P70 lyder.

### 2. UX — dubbeltryck och SELECT-sekvens

Användarens fungerande mönster ombord:

- **SELECT:** håll ~**1,5 s** → släpp → håll ~**1,5 s** (väck + stabil session)  
- **AUTO / STANDBY / läge:** **dubbelklick** (×2); ofta behövs **samma kommando två gånger**  
- Korta SELECT-tryck = bara `display` / wifi, **inga** `command AUTO` i logg → P70 rör sig inte  

### 3. STANDBY upplevs “massa försök”

Loggmönster: första STANDBY → `after` fortfarande AUTO; andra STANDBY eller session end → SK/klocka STANDBY. Pi fick SUCCESS även vid första PUT.

### 4. WIND

Endast **en** `command WIND` i hela serial-loggen (16:03:06) → Pi SUCCESS → klocka visade WIND efter session. I senare pass (16:14–16:20): **inga** WIND-PUT — användaren nådde inte WIND-knappen i UI eller session avbröts.

### 5. Många `watchy-autopilot boot` i serial

Troligen USB-omstart / deep sleep mellan tryck. Vid “inget funkar”-pass: många väckningar, **noll** läges-PUT på flera minuter.

### 6. Act as N2K device = ON

Användaren slog på i Admin → **P70 kunde inte styra piloten alls**. Av igen → normalt. **Behåll `createDevice: false`** på Jubilon (backup `boat-mode-2026-05-31` samma).

Tidigare felaktigt råd i docs: “sätt createDevice på för Watchy” — **gäller inte denna båt**.

## API-referens (oförändrat)

| Action | PUT path | `value` |
|--------|----------|---------|
| AUTO | `steering.autopilot/state` | `"auto"` |
| WIND | `steering.autopilot/state` | `"wind"` |
| STANDBY | `steering.autopilot/state` | `"standby"` |
| ±1 / ±10 | `steering.autopilot/actions/adjustHeading` | `1`, `10`, `-1`, `-10` |

Auth: `Authorization: Bearer` + device token.

- `state` PUT → nästan alltid **202 PENDING**; polla `GET /signalk/v1/requests/{requestId}`  
- `adjustHeading` i STANDBY → **400** (förväntat); i AUTO/WIND → **200**

## Rekommenderad firmware-fix (M3–M4)

**Repo:** `watchy-autopilot` (ej i `jubilon-signalk`)

1. Efter `PUT state`: om status **202** och body `PENDING` → spara `requestId`  
2. Polla `GET /signalk/v1/requests/{requestId}` tills `state==COMPLETED` eller timeout **8–15 s**  
3. Vid COMPLETED → vibration + uppdatera UI som “success”  
4. Öka `SK_PUT_SESSION_TIMEOUT_MS` (nu **3 s**)  
5. Logga: initial HTTP-kod, `requestId`, poll-resultat (`[AP]`-rader)  
6. UI: överväg att inte visa `failed` om GET/state redan matchar kommando efter kort delay  

**Acceptanskriterium båt:** Ett tryck AUTO/STANDBY/WIND → vibration + P70 ändras (användaren tittar P70) utan obligatorisk dubbeltryck.

**Status i git (2026-06-03):** Punkterna 1–5 implementerade i `src/signalk_client.cpp` + `include/config.h`. **M6 = flash + båt re-test.**

## Ombord-workaround (tills firmware är fixad)

1. **P70** är enda feedback som räknas  
2. SELECT **1,5 s + 1,5 s**, vänta på skärm/läge  
3. **Dubbelklick** läge; vid tvekan **samma kommando en gång till** inom 20 s-session  
4. Ignorera vibration och `command failed`  
5. **Act as N2K device = AV**  
6. ± bara när P70 redan i **AUTO** eller **WIND**
